# Tepenia Worked Examples

**What this folder is:** real, concrete run-throughs of the full Pipeline (`../Pipeline/`) applied to actual
characters, from the specific project this whole methodology was originally built and battle-tested in — the
Tepenian Universe (a sci-fi CRPG setting). Kept in its own folder, entirely separate from the Pipeline itself,
so that the Pipeline never depends on this material to function. Nothing here is required reading to use the
Pipeline — it exists purely as demonstration: what does it actually look like to run these tools against a
real character, including the places where the methodology got something wrong and had to be corrected?

**Why this is worth reading anyway:** abstract tools are easier to apply correctly once you've seen them used
for real. Every entry below is checked against the actual character's own established material, with any new
interpretation the exercise generated explicitly flagged as such (never silently presented as if it were
already-settled canon) — the same discipline worth applying to your own characters.

**A deliberate scope limit:** both files below stick to story-craft findings — Lie/Want/Need/Ghost, Impact
Character/Revenant casting, arc type, beat structure — described in terms that hold regardless of medium or
setting, the same discipline the Pipeline itself follows. Neither file documents the source project's own game
mechanics (stat systems, quest-gating math, reputation tracking); those exist, but they're implementation
detail specific to one interactive project, not something a novel, film, or a different game's character
creation would need. Where a project-specific mechanic is genuinely load-bearing to a finding (for instance,
the optional-side-mechanic mistake behind `../Design_Principles/Always_Present_Gating.md`), it's named briefly
and then translated into its medium-agnostic form — the lesson is the point, not the implementation it
happened to occur in.

## Contents

- **`Calethina_Case_Study.md`** — the fullest worked example, covering Stage 4 (Story Material) and Stage 5
  (Beats, Paths & Results) end to end for one deliberately atypical character. Includes a real, caught-in-time
  design mistake and its fix (the origin of `../Design_Principles/Always_Present_Gating.md` and
  `../Design_Principles/Trigger_Type_Pattern.md`), and a genuine open limitation the exercise surfaced in the
  Ending-Shape Cross-Mapping Table rather than smoothing over.
- **`Ayako_Hayashi_Pipeline_Summary.md`** — a second, independent full run of all five stages against a
  different, more typical character, included specifically because a second real-world data point is what
  actually confirms a pattern isn't a one-off coincidence (the Disillusionment-straddle edge case in the
  Ending-Shape table, in particular).
